# XCAR — сервер (регистрация, вход, синхронизация данных)

Бэкенд для приложения XCAR: теперь у него есть полноценный сервер, через который
пользователи **регистрируются и входят** по телефону/e-mail и паролю, а данные
(машины, клиенты, договоры и т.д.) синхронизируются между устройствами через
этот сервер, а не хранятся только в localStorage одного телефона.

## Что внутри

- `POST /api/auth/register` — регистрация (имя, компания, телефон, e-mail, пароль
  + два обязательных согласия — на обработку персональных данных и на условия
  использования; без обеих галочек аккаунт не создаётся)
- `POST /api/auth/login` — вход по телефону или e-mail + паролю, выдаёт JWT-токен
- `POST /api/auth/forgot`, `POST /api/auth/reset` — восстановление пароля по
  e-mail/SMS-коду (см. раздел «Восстановление пароля» ниже)
- `GET  /api/auth/me` — текущий пользователь по токену
- `GET  /api/data` — вся база пользователя (машины, клиенты, договоры…)
- `PUT  /api/data/:key` — сохранить один раздел (именно так синхронизируется
  приложение по мере работы)
- **`/admin`** — супер-админ панель (см. раздел ниже) для управления всеми
  зарегистрированными аккаунтами сервиса
- Пароли хранятся только в виде bcrypt-хэша, никогда в открытом виде
- Данные — в JSON-файлах на диске (`data/users.json` + `data/stores/<id>.json`),
  без внешней СУБД — устанавливать и настраивать ничего не нужно

## Быстрый старт локально

```bash
cd server
npm install
cp .env.example .env      # при желании впишите свой JWT_SECRET — иначе сгенерируется сам
npm start                 # сервер поднимется на http://localhost:8080
```

Проверка:
```bash
curl http://localhost:8080/api/health
```

## Как подключить к приложению (index.html)

В самом начале `index.html` (в первых строках `<head>`) есть строка:

```html
<script>
window.XCAR_API_BASE = 'https://ВАШ-СЕРВЕР.example.com/api';
</script>
```

Замените адрес на реальный адрес вашего развёрнутого сервера (с `/api` на конце)
**после того**, как задеплоите сервер по инструкции ниже. Для локальной проверки
можно временно указать `http://localhost:8080/api`.

Важно: сервер должен быть доступен по **HTTPS**, если приложение установлено как
PWA через GitHub Pages/Netlify (тоже HTTPS) — иначе браузер заблокирует запросы
как небезопасные (mixed content).

## Деплой сервера — самый простой вариант (Render.com, бесплатно)

1. Зарегистрируйтесь на [render.com](https://render.com).
2. Загрузите папку `server/` в свой репозиторий на GitHub (или весь проект).
3. В Render: **New → Web Service** → подключите репозиторий.
4. Настройки:
   - Root Directory: `server` (если сервер лежит в подпапке репозитория)
   - Build Command: `npm install`
   - Start Command: `npm start`
5. В разделе **Environment** добавьте переменные:
   - `JWT_SECRET` — длинное случайное значение (кнопка Generate в Render или
     `openssl rand -hex 32`);
   - `ADMIN_PASSWORD` — ваш пароль для входа в супер-админ панель `/admin`
     (тоже длинный и уникальный — не такой, как у обычных пользователей).
6. Нажмите Deploy. Через пару минут Render выдаст адрес вида
   `https://xcar-server-xxxx.onrender.com` — допишите к нему `/api` и вставьте
   в `window.XCAR_API_BASE` в `index.html`.

Render на бесплатном плане "засыпает" после 15 минут без запросов и просыпается
~30-60 секунд на первый запрос — это нормально для небольшого внутреннего
инструмента; если нужна мгновенная доступность 24/7, возьмите платный план или
разверните на VPS (ниже).

## Деплой на свой VPS (Ubuntu, через PM2 + nginx)

```bash
# на сервере
sudo apt update && sudo apt install -y nodejs npm nginx
cd /opt && git clone <ваш-репозиторий> xcar && cd xcar/server
npm install
cp .env.example .env   # впишите JWT_SECRET
npm install -g pm2
pm2 start server.js --name xcar-server
pm2 save && pm2 startup   # автозапуск после перезагрузки сервера
```

Затем настройте nginx как reverse-proxy с HTTPS (Let's Encrypt / certbot),
проксируя `/api/` на `http://127.0.0.1:8080/`, и укажите итоговый адрес
(`https://ваш-домен/api`) в `window.XCAR_API_BASE`.

## Супер-админ панель (`/admin`)

Сервер сам раздаёт панель управления по адресу `https://ваш-сервер/admin` —
отдельно публиковать её не нужно, никаких дополнительных настроек `XCAR_API_BASE`
тоже (панель сама использует адрес, с которого её открыли).

**Обязательно задайте переменную окружения `ADMIN_PASSWORD`** (длинный
уникальный пароль — не тот, что у обычных пользователей!) — без неё вход в
панель не откроется. В Render: Environment → Add Environment Variable →
`ADMIN_PASSWORD` → сгенерировать значение (кнопка Generate) → Save, затем
передеплоить сервис.

Панель разделена на три вкладки вверху — **Аккаунты**, **Заявки на оплату**
(с бейджем количества новых заявок) и **Настройки**.

Что умеет вкладка «Аккаунты»:
- сводная статистика: сколько всего аккаунтов, машин, клиентов, договоров
  по всем зарегистрированным компаниям;
- список всех аккаунтов с поиском (по компании/имени/телефону/e-mail) и
  бейджем статуса подписки (пробный / активен / истёк) на каждой карточке;
- **создать** новый аккаунт вручную (без прохождения формы регистрации) —
  ему тоже сразу выдаётся пробный период;
- **исправить** основные данные аккаунта (имя, компания, телефон, e-mail);
- **выдать или продлить тариф** вручную, без заявки — выберите тариф и
  количество месяцев на карточке аккаунта;
- сбросить пароль любого аккаунта (если пользователь его забыл);
- удалить аккаунт целиком — вместе со всеми его данными;
- посмотреть и отредактировать данные конкретного аккаунта (машины, клиенты,
  договоры и т.д.) — через JSON-редактор по разделам, с кнопкой
  «Форматировать» для удобства.

Вкладка «Заявки на оплату» — список обращений клиентов «выбрать/продлить
тариф» с их контактами и выбранным тарифом; подтвердите после получения
перевода (указав оплаченное количество месяцев) или отклоните.

Вкладка «Настройки» — редактирование трёх тарифов (название, лимит машин,
цена), длительности пробного периода и реквизитов для перевода, которые
видит клиент. Подробнее — в разделе «Тарифы и подписка» выше.

Важно: если у пользователя в этот момент открыто приложение, оно может по
инерции продолжать сохранять свою локальную копию данных на сервер (фоновая
синхронизация) — тогда ваша правка через админку может быть перезаписана
следующим авто-сохранением из приложения. Правьте данные пользователя либо
когда он точно не работает в приложении, либо предупредите его обновить
страницу после вашего изменения.

Доступ в панель — по паролю (`ADMIN_PASSWORD`), сессия действует 12 часов и
автоматически завершается по истечении — дольше, чем у обычных пользователей,
не выдаётся намеренно, т.к. у панели доступ ко всем данным сразу.

## Тарифы и подписка

У сервиса три платных тарифа (по умолчанию — редактируются в `/admin` →
**Настройки**): **Старт** 1500 ₽/мес (до 3 машин), **Стандарт** 2500 ₽/мес
(до 8 машин), **Бизнес** 4500 ₽/мес (до 15 машин). Новый аккаунт сразу после
регистрации получает **14 дней бесплатного пробного периода** с полным
доступом (тоже настраивается — «Пробный период, дней»).

Как это работает:

- Статус подписки (`trial` / `active` / `expired`) нигде не хранится отдельно —
  он всегда вычисляется на лету из даты окончания (`expiresAt`), поэтому не
  нужен фоновый job: как только время вышло, следующий же запрос уже
  посчитает подписку истёкшей.
- Пока подписка активна (пробный период или оплаченный тариф), приложение
  работает без ограничений.
- Как только подписка истекает, в приложении блокируются три действия:
  **добавить расход**, **добавить доход** (платёж) и **оформить новый
  договор** — на клиенте выводится сообщение «Подписка неактивна» со ссылкой
  на экран «Тариф». Это ограничение — только на стороне интерфейса.
- Лимит машин по тарифу, наоборот, **проверяется на сервере** (`PUT
  /api/data/cars` и `PUT /api/data/:key` при `key=cars` отвечают `403`, если
  машин больше, чем разрешает тариф) — это единственное ограничение, которое
  нельзя обойти в браузере. Приложение дополнительно блокирует кнопку
  «Добавить машину» заранее, чтобы пользователь не заполнял форму впустую.
- На экране «Настройки → Тариф» кнопка называется «Подключить», если
  подписка истекла, и «Продлить», если она ещё активна/пробная. После
  выбора тарифа клиент попадает на экран выбора срока — **1, 3, 6 или 12
  месяцев** (сумма = цена тарифа × количество месяцев, считается на
  сервере, а не берётся из того, что прислал клиент) — и вписывает номер
  телефона (необязательно телефон аккаунта — например, если платить будет
  другой человек). После отправки создаётся заявка (`POST
  /api/billing/request { planId, months, contactPhone }`), и сразу
  показываются реквизиты для перевода (плюс QR-код, если вы его загрузили —
  см. ниже). Заявка появляется у вас в `/admin` → **Заявки на оплату** — со
  статусом «Ожидает», сроком, посчитанной суммой и указанным клиентом
  номером. Счётчик новых заявок на этой вкладке обновляется сам каждые 45
  секунд, даже если вы не переключались на неё — сразу видно, что кто-то
  оплатил и ждёт подключения.
- Оплата происходит вручную, переводом (никакого платёжного шлюза нет) —
  когда деньги пришли, откройте заявку в `/admin` (поле «сколько месяцев»
  уже предзаполнено тем сроком, который выбрал клиент — можно поправить,
  если нужно) и нажмите «Подтвердить». Подписка продлевается от большей
  из дат (сейчас / текущее окончание), т.е. досрочное продление не «сгорает».
  Там же можно и вручную выдать/продлить тариф конкретному аккаунту без
  заявки — на карточке аккаунта в `/admin`.
- Реквизиты для перевода (получатель, банк, номер карты, телефон для СБП,
  комментарий, QR-код) задаются в `/admin` → **Настройки** — именно их
  увидит клиент при выборе/продлении тарифа. QR-код загружается файлом
  (картинка, до 3 МБ) прямо в браузере — конвертируется в base64 и
  хранится вместе с остальными реквизитами в `data/config.json`; поле
  необязательное, если не загружено — клиент просто не увидит картинку.
  Заполните реквизиты перед реальным запуском — по умолчанию поля пустые.

## Восстановление пароля

На экране входа у клиента есть ссылка «Забыли пароль?»: он указывает
телефон или e-mail, получает 6-значный код (действует 15 минут) и задаёт
новый пароль. Как и с реквизитами для перевода — чтобы это реально
отправляло письма/SMS, а не только показывало форму, нужно один раз
заполнить настройки в `/admin` → **Настройки**:

- **Почта (SMTP)** — сервер сам умеет отправлять письма через любой обычный
  SMTP (не нужен сторонний сервис вроде SendGrid): подойдёт, например,
  Яндекс.Почта (`smtp.yandex.ru`, порт 465, SSL) или Gmail (`smtp.gmail.com`,
  порт 587). У большинства почтовых сервисов для стороннего приложения
  нужен не обычный пароль от ящика, а отдельный **«пароль приложения»** —
  создаётся в настройках безопасности почты.
- **SMS** — через [smsc.ru](https://smsc.ru), популярный российский SMS-шлюз
  с простым HTTP API; нужен аккаунт на smsc.ru (логин + пароль/API-ключ,
  пополненный баланс). При желании можно подключить другого провайдера —
  для этого достаточно переписать один файл `server/lib/sms.js`, остальной
  код (роуты, клиент) трогать не нужно.

Пока оба блока настроек пустые, соответствующий способ восстановления
**не отправляет** ни письма, ни SMS — вместо этого код просто выводится в
лог сервера (`console.warn`), чтобы разработчик мог проверить сценарий
локально без реальной почты/SMS. Клиенту при этом всегда отвечает «код
отправлен» независимо от того, настроен канал или нет, и независимо от
того, найден ли такой телефон/e-mail в базе, — это осознанное решение,
чтобы через форму восстановления нельзя было перебором узнать, кто
зарегистрирован в сервисе.

Дополнительные меры защиты (не требуют настройки): код действует 15 минут
и одноразовый; повторный запрос кода раньше, чем через минуту, не создаёт
новый код (чтобы не заспамить почту/телефон повторными отправками); на
подбор кода даётся не более 5 попыток, после чего код аннулируется и нужно
запросить новый; отдельный лимит запросов в `/auth/forgot`/`/auth/reset`
по IP защищает от массового перебора.

## О согласии на обработку персональных данных (152-ФЗ)

При регистрации сервер требует два подтверждённых чекбокса и фиксирует факт и
время согласия (с IP-адресом) в `data/users.json` — это то, что реально должен
уметь доказать оператор персональных данных по 152-ФЗ. Тексты согласия,
пользовательского соглашения и политики конфиденциальности лежат в клиенте
(`index.html`, объект `LEGAL_TEXTS`) в виде **типового шаблона** — это не
юридическая консультация. Перед реальным использованием сервиса:

- впишите свои реальные реквизиты (наименование ИП/ООО, ИНН) вместо `[...]`;
- при необходимости покажите тексты юристу и/или зарегистрируйтесь как оператор
  персональных данных в Роскомнадзоре, если это требуется для вашего случая.

## Резервные копии

Файлы `data/users.json` и `data/stores/*.json` — это вся база. Регулярно
копируйте папку `data/` (например, cron + `rsync`/архивирование) на случай
сбоя диска — встроенного облачного бэкапа в этой версии нет.
